# Daywork implementation contract

Ontario / CAD. Production private preview until operator configures live payments, verified mail, terms and business. Do not imply all workers get same-day bank arrival.

Stack React+Vite, Hono API, Cloudflare Worker + D1. Shared TypeScript in src/shared/types.ts (backend agent owns). DB schema in migrations (backend owns). Root owns src/server/index.ts, config, package scripts, CI, docs, e2e tests. Backend agent owns src/server/auth.ts, middleware.ts, marketplace.ts, types.ts, migrations, shared files, backend tests. Payment agent owns src/server/payments.ts and tests, own migration 0002_payments.sql.

Hono type: export type AppEnv = { Bindings: Env; Variables: {user: User | null} } in src/server/types.ts. Env generated by wrangler types. Optional secrets merged via src/server/secrets.d.ts global interface Env: STRIPE_SECRET_KEY?, STRIPE_WEBHOOK_SECRET?, STRIPE_CONNECT_WEBHOOK_SECRET?, RESEND_API_KEY?, TURNSTILE_SECRET_KEY?. Config vars APP_ENV string, APP_URL string, LAUNCH_MODE 'preview'|'live' (string typing okay), EMAIL_FROM string, SUPPORT_EMAIL string, ADMIN_EMAILS string, TURNSTILE_SITE_KEY string. DB binding DB. ASSETS binding ASSETS. Frontend sends same-origin JSON, API rejects cross-origin unsafe methods. Responses {error:string} on errors. GET /api/config returns {launchMode,currency:'CAD',region:'Ontario',authReady,paymentsReady,turnstileSiteKey,supportEmail,fee:{percent:12,fixedCents:100,minimumCents:300}}.

Auth passwordless verified magic links. POST /api/auth/request {email,name?,role:'worker'|'poster'|'both',turnstileToken?,consent:true} returns generic success. Production fails clearly 503 if email provider not set; LOCAL APP_ENV only returns devToken, never production. POST /api/auth/verify {token} consumes single-use hash and issues httpOnly Secure SameSite=Lax cookie (no Secure on local). GET /api/me returns {user:null|User}; PATCH /api/me {name,bio,city,skills}; POST /api/auth/logout. User fields id,email,name,role,bio,city,skills,created_at,stripe_account_id?; worker/poster ability can overlap.

Marketplace GET /api/jobs?q=&city=&category=&schedule=&page= -> {jobs:Job[],total,page}. GET /api/jobs/:id -> {job,milestones,applications?,myApplication?,messages?,reviews?}. Job snake_case fields id,poster_id,worker_id nullable,title,description,category,city,area,start_date,estimated_hours,budget_cents,status('open','assigned','in_progress','completed','cancelled','disputed'),payment_schedule('completion','milestones'),created_at,poster_name. No street addresses public. POST /api/jobs {title,description,category,city,area,start_date,estimated_hours,milestones:[{title,amount_cents}]} -> {job}; category enum Cleaning,Yard work,Moving help,Assembly,General help. Minimum milestone CA$25; max job CA$5000, max5 milestones; totals computed server-side. Live marketplace mutations require LAUNCH_MODE=live (APP_ENV local tests bypass preview gating). Preview allows waitlist only. Example listings frontend only and always clearly labelled not bookable.
POST /api/jobs/:id/apply {message}; POST /api/jobs/:id/hire {applicationId}; POST /api/jobs/:id/start; POST /api/jobs/:id/cancel; POST /api/jobs/:id/messages {body}; POST /api/jobs/:id/reviews {rating,body}; POST /api/jobs/:id/report {reason}; GET /api/dashboard -> {posted,assigned,applications}; POST /api/milestones/:id/submit; POST /api/milestones/:id/approve. Milestone fields id,job_id,title,amount_cents,position,status ('pending','submitted','approved','checkout_pending','paid','refunded'), checkout_session_id? payment_intent_id? paid_at? fee_cents? Payment agent owns extending schema. Use conditional state updates and D1 batches for atomic hire. Approval means ready for poster payment, NOT funded or bank payout.
POST /api/waitlist {email,city,role,consent:true,turnstileToken?} persisted, consent timestamp; no marketing email sending now. GET /api/admin/overview and reports moderation only configured ADMIN_EMAILS signed-in verified user. Suspended user cannot use mutations.

Payments routes exported Hono<AppEnv> payments; mounted at /api. Auth helper requireUser middleware from auth.ts or middleware.ts; coordinate. POST /api/payments/onboard -> {url}, GET /api/payments/status -> {configured,accountReady,onboardingComplete,chargesEnabled,payoutsEnabled,balance?,payouts?,instantEligible?,message?}, POST /api/payments/dashboard -> {url}, POST /api/milestones/:id/checkout -> {url}; POST /api/payments/payout {method:'instant'|'standard',amount_cents,requestId:UUID} -> payout. POST /api/webhooks/stripe and /api/webhooks/stripe-connect public SIGNED raw body. No money mutation unless live and Stripe configured. Destination Checkout per APPROVED milestone; poster charged worker amount + max(3CAD,12%+1CAD) fee. Stripe Accounts v2 hosted onboarding. Idempotency everywhere, durable payment attempts, validate webhook amount/currency/account/metadata, no paid-on-redirect. Refund admin route with reverse_transfer/refund_application_fee, idempotency; reports freeze payments. Payout fees platform absorbed, no guarantee bank timing. Stripe-dependent tax config launch checklist, do not claim compliance.
